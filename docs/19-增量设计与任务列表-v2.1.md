## 3. 事实基线：v2.0 遗留的 5 个缺口

> 全部来自 2026-10-22 代码核查，均为「5 天零调仓 + 零止损」掩盖下的暗雷。

| # | 缺口 | 代码证据 | 现状后果 | 未暴露原因 |
|---|---|---|---|---|
| 1 | 新开仓不注册止损 | `src/live/` 9 模块 **0 处** `register_entry`；仅 `portfolio_engine.py:233` 有 | 真实调仓后止损永不触发 | 5 天零调仓 |
| 2 | 加仓不重估、平仓不清除 | `adapter.py:352` 只在「止损单全成」后 `notify_stop` | 加仓后固定止损挂旧价；普通平仓后状态残留 | 无调仓 |
| 3 | `stopped_today` 永不清理 | `risk.py:369 new_day()`，生产路径 **0 调用**（仅 tests） | 一次止损 → 该品种**永久**禁止开仓 | 无止损 |
| 4 | 信号释放从未调用 | `LiveRiskGuard.update_signal`（`risk_guard.py:176`）无调用点；回测每日调（`portfolio_engine.py:358`） | `signal_reset` 的 `dir_lock` 永不解 → 与 3 叠加成死锁 | 无止损 |
| 5 | 当日基准不推进 | `ledger.py:214 begin_day()` 仅 tests 调用 | 日报/库 `day_pnl` 实为**累计**盈亏 | 波动小，未核 |

**结论**：v2.1 的 P0 不是「补一行注册」，而是补齐回测那条
「每日信号释放 → 开仓注册 → 加仓重估 → 归零清除 → 日初重置」的时序线。

## 4. 设计

### 4.1 T2.1-1 成交后止损状态同步

**为什么不能只在开仓时注册**：回测的 `register_entry_stops`（`portfolio_engine.py:230`）
在**每一次成交后**调用，三分支语义——`pos==0 → clear`、方向不同 → `register_entry`、
同向 → `update_entry`。只在开仓调一次，会让「加仓」「平仓后同向重开」两种情形错位。

**接口**（`src/live/risk_guard.py` 新增方法，不改 engine）：

```python
def sync_stops(self, symbol: str, row_idx: int | None = None) -> list[RiskEvent]:
    """成交后同步止损状态（对齐 portfolio_engine.register_entry_stops 三分支）。"""
    row = self.ledger.day_idx if row_idx is None else int(row_idx)
    pos = self.ledger.net_size(symbol)
    if pos == 0:
        had = self.manager.stops.state(symbol) is not None
        self.manager.stops.clear(symbol)
        return [RiskEvent("", "stop_clear", symbol, "持仓归零 → 清除止损状态")] if had else []
    direction = 1 if pos > 0 else -1
    avg = float(self.ledger.state(symbol).avg_price)
    st = self.manager.stops.state(symbol)
    if st is None or st.direction != direction:
        atr = float(self.atr_hint.get(symbol, 0.0))
        self.manager.stops.register_entry(symbol, direction, avg, atr, row)
        kind = "stop_register"
        detail = f"建立止损：{direction:+d} @ {avg:.4f}，ATR {atr:.4f}，基准日 {row}"
        if atr <= 0:
            kind, detail = "stop_register_no_atr", f"建止损但 ATR 缺失（仅止盈可用）：{direction:+d} @ {avg:.4f}"
        return [RiskEvent("", kind, symbol, detail)]
    self.manager.stops.update_entry(symbol, avg)
    return [RiskEvent("", "stop_update", symbol, f"加仓重估：均价 {avg:.4f}")]
```

**挂点**：`adapter.on_event` 的 `TradeRtn` 且 `fresh` 分支，`ledger.apply_fill(...)` 成功之后：

```python
sym = self.ledger.instrument_map.get(ev.instrument)
if sym:
    for e in self.guard.sync_stops(sym):
        out.append(ExecNote("risk", sym, e.detail))
```

**ATR 传递**：`LiveRiskGuard` 新增 `self.atr_hint: dict[str, float] = {}`；
`execute_round` 在 `bridge.compute()` 后写入 `self.guard.atr_hint = dict(self.bridge.last_atr)`。
时点对齐：执行发生在 T 日开盘，ATR 数据截至 T-1 收盘，等价回测的 `iloc[row_idx-1]`。

**幂等性**：部分成交会多次回调；`pos` 不变时走 `update_entry`，均价不变 → 固定止损重算结果不变，可安全重复。

**新仓保护基准**：`row_idx = ledger.day_idx` → `_armed` 要求 `row_idx > entry_row`，
即成交当日不判定、次一交易日起保护，与回测「同行不判定」一致。

### 4.2 T2.1-2 每日信号释放

回测每日成交前调 `guard.update_signal(s, sig, day_idx)`（`portfolio_engine.py:358`），
`sig` 取信号日收盘信号。live 的 `TargetPosition.signal`（`signals.py:41`）就是同一口径。

**落点**：`run_live.execute_round()`，`targets = self.bridge.compute()` 之后、`execute_target` 之前：

```python
for s, t in targets.items():
    self.guard.update_signal(s, t.signal)
```

顺序不可换：必须在 `gate_open` 的「重入锁定」判定之前释放，否则同一天会多锁一天。
`--force-target` 覆盖 targets 时**保留原 `signal`**，避免释放逻辑失真。

### 4.3 T2.1-3 日初重置与当日基准（含 T2.1-5）

**落点**：`run_live.settle_day()` 末尾，现有 `self.ledger.day_idx += 1` 之后追加两行：

```python
self.ledger.last_settle_date = date
self.ledger.day_idx += 1
self.ledger.day_ref_equity = self.ledger.equity   # 新增：次日「开盘前权益」
self.guard.new_day()                              # 新增：清 stopped_today
```

**顺序约束**：`day_pnl = equity - day_ref_equity` 在写库时（`run_live.py:414`）已算完，
因此基准必须在日报/入库**之后**更新，否则当日盈亏会被算成 0。

**效果**：T2.1-5 自动修复——日报与 `live_equity.day_pnl` 从「累计」变为「单日」。

**已知限制（不做补偿）**：若进程在 15:05-21:00 之外离线导致当日未结算，
`day_idx` 不推进、`stopped_today` 不清、`day_pnl` 跨两日。处置：
+ 启动时比对 `last_settle_date` 与上一工作日，落后 >1 天则 `journal.log("settle_missed")` 并在日报标注「跨日口径」；
+ 不自动补做（补做需要历史快照，超出本期范围）。

### 4.4 T2.1-4 启动补建

**落点**：`run_live.start()`，`ledger.load / guard.load / bridge.load` 之后、连接柜台之前：

```python
for s in self.symbols:
    if self.ledger.net_size(s) != 0 and self.guard.stop_state(s) is None:
        self.guard.atr_hint = dict(self.bridge.last_atr)
        evs = self.guard.sync_stops(s, row_idx=self.ledger.day_idx - 1)
        for e in evs:
            self.journal.log("stop_backfill", symbol=s, detail=e.detail)
```

**`row_idx = day_idx - 1`**：把已有持仓视为「昨日入场」→ 补建后**立即受保护**。
若价格已越过止损位，下一个 tick 即触发平仓——这是**正确暴露**（回测里早该平掉），
记 `stop_backfill_triggered` 事件，不算故障。**首次上线可能因此立即平仓，属预期。**

**ATR 持久化**：`SignalBridge.to_dict` 增加 `"last_atr": {...}`，`load` 读取（缺省 `{}`，
兼容 v2.0 的 `signal_state.json`）。缺失时 `atr_entry=0` → 只有止盈可用，
`stop_register_no_atr` 事件 + 日报红字告警。

### 4.5 T2.1-6 任务链看门狗（P1）

**现状**：`register_task.py:100-106` 每 5 分钟触发 `scripts/live_run.bat`，
bat 直接冷启 python；`run_live.py:86` 的端口锁（49156）保证只有一个真跑，锁失败 `return 0`（`run_live.py:616-619`）。
所以「换代」不是并发，而是**每次触发都白起一个 cmd + python**（5 天 39 个 session 即证据），
撞 9:00 执行或 15:05 日终窗口会漏一次。

**方案：只探端口，不启 python。**

新增 `scripts/live_guard.ps1`：

```powershell
$port = 49156
$alive = $false
try {
  $c = New-Object System.Net.Sockets.TcpClient
  $iar = $c.BeginConnect('127.0.0.1', $port, $null, $null)
  if ($iar.AsyncWaitHandle.WaitOne(300)) { $c.EndConnect($iar); $alive = $true }
  $c.Close()
} catch { $alive = $false }
if ($alive) { exit 0 }
Start-Process -FilePath ".venv\Scripts\python.exe" `
  -ArgumentList "run_live.py","--real" -WindowStyle Hidden `
  -RedirectStandardOutput "logs\live_task.log" -RedirectStandardError "logs\live_task.err.log"
```

`scripts/live_run.bat` 改为只调它（**必须 CRLF**，沿用 v2.0 教训）：

```bat
@echo off
cd /d "%~dp0.."
powershell -NoProfile -ExecutionPolicy Bypass -File "scripts\live_guard.ps1"
```

任务计划不变（每 5 分钟触发 bat）。效果：存活时只花一次 TCP 连接（毫秒级）+ powershell 启动；
真死时 ≤5 分钟拉起。换代从「每 5 分钟」降到「仅真死时」。

**失效条件**：进程卡死但端口仍占用 → 探测显示存活、看门狗不会重启。
兜底是 v2.0 已有的「连接失联 3 分钟主动 `SystemExit`」（`run_live.py:496-511`）。

### 4.7 T2.1-8 `--force-target` 联调参数（P2）

```
uv run python run_live.py --once --real --force-target "M0=+1,RB0=-2"
```

规则：
+ 仅 `--once` 允许（常驻模式传该参数直接报错退出），防误用；
+ 仍先跑 `bridge.compute()`（拿 `last_atr` / `last_close` / 原信号），只覆盖 `direction` 与 `lots`；
+ 走完整 `execute_target` 链路（gate_open → 下单 → 回报 → 账本 → `sync_stops`）。

**止损触发演练**：新仓当日不 armed，需次日触发。用 `config.local.yaml` 临时覆盖
`risk.stops.fixed.atr_mult: 0.05`（极小止损距离），次日开盘必触发；演练后删除该覆盖（**不入库**）。

## 6. 测试清单（轮 1 交付）

1. `sync_stops` 新开仓 → 建立 state（direction/entry/fixed/trail 正确）

3. 持仓归零 → `clear` + `stop_clear` 事件

5. 启动补建：有仓无状态 → 补建成功 + `row_idx = day_idx-1` → 当 tick 即 armed

8. `new_day` 清 `stopped_today`
9. `settle_day` 后 `day_ref_equity == equity`
10. `day_pnl` 口径：结算前后各算一次，等于单日权益差

## 7. 风险与失效条件（如实记录）

| 风险 | 影响 | 缓解 |
|---|---|---|
| 日终漏做 → `day_idx` 不推进 | `armed` 永不成立、`day_pnl` 跨日 | `settle_missed` 事件 + 日报标注；不自动补做 |
| 补建 ATR 缺失 | 只剩止盈，风险敞口放大 | 事件 + 日报红字；优先修数据再上线 |
| 看门狗探测不到「卡死但端口在」 | 进程假活 | 依赖 3 分钟主动退出（已存在） |
| 补建首日批量平仓 | 权益跳变、回归数据脏 | 属正确暴露；演练日单独记录，不混入回归统计 |
| `--force-target` 误用 | 非预期下单 | 仅 `--once`；日志标注 `force_target`；不入任务计划 |
| 夜盘缺失 | 夜盘段无止损监控 | 已知口径，回测对比如实计入 |

### A.5 看门狗自身的坑（R4，2026-10-23 实测）

首次实现用 `Start-Process -WindowStyle Hidden` 拉起 python，实测**从来没成功过**：

- 报错：`已添加项。字典中的关键字:“http_proxy”所添加的关键字:“HTTP_PROXY”`；
- 原因：PowerShell 5.1 的 `ProcessStartInfo.Environment` 是大小写不敏感字典，而本机环境里
  `http_proxy` 与 `HTTP_PROXY` 同时存在 → 构建子进程环境时抛异常；
- 更糟的是脚本 `$ErrorActionPreference='SilentlyContinue'`，异常被吞、脚本仍 `exit 0`，
  任务计划显示「成功」，实际根本没启动进程。

修复：改用 `System.Diagnostics.ProcessStartInfo` + `UseShellExecute = $true`（不构建环境字典）；
异常改为写 `logs/live_guard.err.log` 并 `exit 1`；脚本存为 CRLF（沿用 v2.0 教训）。

**验证**：14:50 计划任务用修好的脚本自动拉起实例（PID 14596），端口监听、3 个止损状态恢复、
执行轮「全部品种差额为 0（无调仓）」，无重复下单。

**代价（如实记录）**：14:46 手工 kill 旧实例后，因看门狗失效，14:46–14:50 约 4 分钟无监控
（当时持仓 3 个品种、日盘仍在交易）。该缺口计入验收记录。
