## 3. 架构设计

### 3.1 总体原则

- **双账本分离**：SimNow 柜台账（2000 万，只管成交与持仓）+ 本地**虚拟账本**（10 万口径，权益 / 风险预算 / 熔断全按它算）——策略逻辑与资金约束解耦，验收可逐笔对账；
- **引擎零改动**：策略 `on_bar` 接口不变；仿真通过「重放历史日线」调用同一套策略代码（复用 `src/strategy` 注册表与 `src/engine/sizing` 手数逻辑）；
- **每日重放信号**（关键设计）：收盘后用**全量历史数据重放**策略 → 得到目标仓位。幂等、可重启、与回测计算路径零偏差（不用「进程内增量状态」，避免状态漂移）；
- **薄适配器**：openctp-ctp 只做「管道」（回调 → 线程安全队列）；连接编排 / 订单管理 / 风控 / 账务全在自研层 `src/live/`；
- **可选依赖隔离**：`openctp-ctp` 进入可选依赖组 `live`（`uv sync --extra live`），主链路（回测）依赖零变化；
- **零回归**：既有 150 测试零改动全绿；回测 / 组合 / 每日流水线行为不变；一切开关默认关（`live.enabled: false`）。

### 3.3 进程模型（run_live.py）

单进程 + 线程（openctp-ctp 回调发生在 C++ 线程，必须与业务隔离）：

```
┌─ 主线程：事件循环 ────────────────────────────────────┐
│  消费事件队列（行情 / 回报 / 定时器）→ 业务状态机        │
│  ├─ 连接状态机：断连→连接→认证→登录→结算确认→就绪       │
│  │    （行情与交易两路独立；退避重连 5/10/30/60s）       │
│  ├─ 时段调度：夜盘 21:00 执行 / 盘中 tick 风控 / 15:05 日报 │
│  └─ 状态持久化：账本 / 熔断状态 / 订单簿 → 磁盘（重启恢复）│
└───────────────────────────────────────────────────────┘
    ↑ 投递事件（不执行业务）        ↑ 投递事件
┌─ MD 回调线程（库内部）┐    ┌─ TD 回调线程（库内部）┐
│  OnRtnDepthMarketData │    │  OnRtnOrder / Trade   │
└───────────────────────┘    └───────────────────────┘
```

- **行情用途**：① 执行时点取开盘价（首个 tick 的 `open_price`）；② 止损止盈 tick 触价判定；③ 涨跌停方向判定。不做行情落库（日线数据仍走 akshare 链路）；
- **心跳与自愈**：交易时段内 >30s 无行情 → 告警 + 触发重连；TD 定期查询（遵守 CTP 查询流控 1 秒/次）；
- **优雅退出**：收到退出信号 → 保存状态 → 断开连接 → 退出码 0（供任务计划判断）。

### 3.4 信号与执行流程（核心口径）

以自然日 M 的视角（M 日 21:00 夜盘属于下一交易日 M+1）：

| 时点 | 动作 | 说明 |
|---|---|---|
| M 日 15:00 | 日盘收盘 | —— |
| M 日 17:00 | **信号计算**（复用 daily_run 时点） | 数据更新（复用）→ 重放全量日线 → 8 品种目标仓位（方向 + 手数）→ 写入事件流 / DB |
| M 日 21:00:05 | **执行目标仓位**（交易日 M+1 开盘） | 目标 vs 实际持仓 → 差额订单（先平后开）→ 风控闸门 → 限价报单 |
| M 日 21:00 ~ M+1 日 15:00 | **盘中风控** | tick 触价 → 止损止盈平仓单；敞口 / 流动性 / 涨跌停实时检查 |
| M+1 日 15:05 | **收盘处理** | 权益快照 → 对账 → 日报（企微 + 落地 md）；熔断收盘判定（次日生效） |

**信号计算**（`signals.py`）：
- 用**全量历史 clean CSV**（复用 `daily_run` 更新后的数据）重放策略至最新 bar → 取目标仓位；
- 手数计算复用 `sizing` 逻辑（atr_risk：权益 × 1.5% 风险预算 → 手数），权益来自虚拟账本 → **与回测逐项一致**；
- 输出「目标仓位表」：`{symbol: {direction, lots, signal_date, ref_price}}`。

**下单执行**（`adapter.py` + `orders.py`）：
- 差额订单按「**先平后开**」拆分（与回测 broker 口径一致）；方向翻转 = 平仓 + 反向开仓两笔；
- **限价追单**：以开盘价 ±1 跳挂单（买 `open+1` 跳 / 卖 `open-1` 跳）；5 秒未全成 → 撤单追价 1 跳，最多追 3 次；仍未成交 → 记录「未成交」事件 + 告警（**不自动转市价**，次日信号重算时自动重试，不丢信号）；
- **交易所差异**：上期所品种（RB0 / AL0）平仓拆分为平昨 / 平今（`CLOSEYESTERDAY` / `CLOSETODAY`）；大商所 / 郑商所直接 `CLOSE`；
- **合约映射**：主力连续 → 实际合约（如 `RB0 → rb2601`），映射表在轮 1 用实时行情实测确定；郑商所代码为 3 位数字（如 `SR701`），上期所 / 大商所为 4 位（如 `rb2601`、`m2601`）。

**关键口径确认项**（轮 1 探针时实测，不猜）：
- akshare 日线的 `open` 对应「夜盘 21:00 开盘」还是「日盘 9:00 开盘」——将 akshare 某日 open 与 SimNow 同日 tick 的 21:00 / 9:00 开盘价对比：
  - 若为夜盘口径 → 21:00 执行完全对齐（预期情形）；
  - 若为日盘口径 → 记录系统性偏差说明，评审决定调整执行时点或保留（偏差幅度实测后量化）。

### 3.5 虚拟账本（ledger.py）

- 初始权益 `nominal_capital = 100000`；账务口径与 `portfolio_engine` 的账户模型**逐项对齐**：平仓盈亏（按成交价）、手续费（config 口径）、保证金占用（合约参数 × 手数）、每日权益盯市（收盘价）；
- 完整模拟「可用资金」约束：不足 → 按可负担手数降级（`margin_degrade` 口径，与 v1.3 一致）；
- 状态持久化：`output/live/state/ledger.json`（每次成交 / 收盘快照后落盘，重启从磁盘恢复）；
- 异常护栏：单日权益变动幅度超阈值 → 日报标注 + 告警（防程序 bug 造成的账务漂移）。

### 3.6 风控实时化（risk_guard.py，全量对齐 v1.3）

**下单前闸门**（顺序固定，任一不通过 → 拒单 + 记录事件）：

| 序 | 检查 | 口径 |
|---|---|---|
| 1 | 熔断状态 | 冷却期 / 降级期中 → 拒开仓（平仓不受限） |
| 2 | 资金 | 虚拟账本可用资金；不足 → 降级手数或拒绝 |
| 3 | 敞口 | 单品种 / 组合总名义 ≤ 权益 × 上限（150% / 400%） |
| 4 | 流动性 | 报单量 ≤ 当日累计成交量 × 5%（实时近似） |
| 5 | 涨跌停 | 跌停拒卖 / 涨停拒买（按最新 tick 判定方向） |

**盘中止损止盈**：
- 固定止损 2×ATR（入场冻结）、移动止损 3×ATR（极值追踪）、止盈默认关（与 v1.3 默认一致）；
- ATR 用「截至前一交易日」日线计算（防未来函数，与回测口径一致）；
- tick 触价 → 立即生成平仓单（走闸门）；触发价与成交价偏差记录到事件流（复盘用）。

**熔断**：日盘收盘后判定（组合级：日损失 3% / 回撤 15% 降级 / 连亏 5 笔）→ 次日生效；状态持久化（重启不丢）。

**重入**：signal_reset 口径（止损后等信号重置，与回测一致）。

### 3.7 监控、日报与守护（T2.0-5）

- **事件流**：`output/live/journal/live_<YYYYMMDD>.jsonl`（信号 / 订单 / 成交 / 风控 / 连接 / 异常），同时登记 DB；
- **每日日报**（15:05）：当日信号与执行结果、订单 / 成交明细、双账本持仓与权益（虚拟 + 柜台）、风控事件、连接事件、未成交 / 异常提示 → 企微推送（复用 `notify`）+ 落地 `output/live/reports/日报_<YYYYMMDD>.md`；
- **断线重连**：行情 / 交易两路独立监控；退避重连后重新认证 / 登录 / 结算确认 / 恢复订阅；断连期间信号执行顺延（记录后重连补发）；
- **进程守护**：`register_task.py --live` 注册任务计划——开机自启（ONSTART + 延迟 1 分钟）+ 任务失败自动重启；另提供「禁休眠 / 睡眠检查」提醒清单（附录 B）；
- **停机开关**：`live.enabled: false` 或进程优雅退出（收盘后停机不丢状态）。

## 5. 验收标准（对 docs/07 验收线的细化）

1. **连续 5+ 交易日无人值守**：验收期内进程自动运行（含夜盘），每日日报自动生成 / 推送，无需人工干预（除观察与记录）；
2. **信号一致性抽查**：随机抽 3 个交易日，用同一数据跑回测对照 → 目标仓位（方向 / 手数）逐品种一致；
3. **对账通过**：验收期内每日对账——持仓一致、成交笔数一致（申报未成交的差异需有事件记录）、权益趋势核对通过；
4. **风控实测**：闸门拦截 / 止损触发 / 熔断状态至少各实测 1 次（可构造）；事件与规则逐项可对；
5. **断线恢复**：验收期内发生断线时自动恢复（或注入测试：手动断网 → 自动重连 → 状态无损）；
6. **安全默认**：`live.enabled` 默认 false、`dry_run` 默认 true；真实下单需显式开启（防误跑）；
7. **零回归**：既有 150 测试零改动全绿 + 新增测试；CI 全绿；engine / strategy / analysis 及 data 既有文件 `git diff` 为空；
8. **文档与合规**：README 含「如何启动 / 停机 / 看日报」；日报与 README 明示「模拟 ≠ 实盘，仿真只验证工程链路，不代表实盘收益」。
