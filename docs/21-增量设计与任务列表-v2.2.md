## 4. 设计

### 4.1 T2.2-1 合约生命周期元数据与状态机

**为什么不用「从合约代码推算」**：`al2611` → 年份 26、月份 11 可以解析，但「最后交易日」依赖交易所规则
（SHFE 15 日 / DCE 第 10 个交易日 / CZCE 第 10 个交易日）与节假日顺延，规则每年都在微调；
算错一天的代价是被强平。**因此：脚本按规则出建议，人工确认后落静态表，运行时只读表。**

新增 `src/live/lifecycle.py`（**纯函数 + 数据类**，不碰 CTP / 账本 → 可全量单测）：

```python
"""合约生命周期（v2.2）：到期状态机 + 移仓计划数据结构。

设计原则：
- 纯函数 + 数据类，不碰 CTP、不碰账本 → 全量单测覆盖；
- 到期判定用「自然日倒计时」，不引入交易日历依赖（阈值保守，宁可早禁一天）；
- 元数据来自 config/contracts_lifecycle.yaml（roll_plan.py 出建议，人工确认）。
"""

@dataclass(frozen=True)
class ContractLife:
    instrument: str
    symbol: str            # 品种（RB0）
    exchange: str
    last_trade: dt.date
    individual_last: dt.date   # 自然人最后了结日（保守）

class LifecycleBook:
    def __init__(self, cfg: dict, contracts_map: dict[str, str]) -> None: ...
    def state(self, symbol: str) -> str:
        """ok | warn | block | force_close | unknown"""
    def days_left(self, symbol: str) -> int
    def can_open(self, symbol: str) -> tuple[bool, str]
    def missing(self) -> list[str]:
        """有 mapping 但无生命周期条目的品种（启动告警用）"""
```

**状态机（阈值全 config 化）**：

| 状态 | 条件（距 `individual_last`） | 动作 |
|---|---|---|
| `ok` | > `warn_days`（默认 5） | 正常 |
| `warn` | ≤ 5 天 | **禁新开** + 日报 / 企微提示 |
| `force_close` | ≤ `force_close_days`（默认 1）且仍持仓 | **自动全平**（每小时重试） |
| `unknown` | 无元数据条目 | **禁新开** + 启动告警（不允许「未知合约」开仓） |

```yaml
live:
  lifecycle:
    enabled: true
    warn_days: 5
    force_close_days: 1
    roll_trigger_days: 10      # ≤10 天 且 主力已切换 → 出移仓计划
    main_switch_ratio: 1.2     # 候选持仓量 > 当前 × 1.2
    main_switch_days: 2        # 连续 2 个交易日满足才算切换（防抖）
```

**`unknown` 为什么禁开**：新加品种忘登记是最可能的失误模式；宁可启动就报错，也不要静默开进一个即将到期的合约。
提供 `--allow-unknown`（仅 `--once` 联调用），常驻模式不允许。

### 4.2 T2.2-2 到期硬闸（三处检查点）

| 检查点 | 位置 | 覆盖场景 |
|---|---|---|
| 启动 | `LiveRuntime.start()`，`_backfill_stops()` 之前 | 进程重启后立刻知道「持仓合约要到期了」 |
| 执行轮 | `Executor.execute_target()` 逐腿 `gate_open` **之前** | 每日 09:00 的目标执行 |
| 盘中 | `run_forever` 每小时（`last_life_check`；进程常驻，非交易时段也跑） | 跨过 T-5 / T-1 边界时立即生效，不必等次日开盘 |

**优先级高于熔断**：到期强平是交易所强制，不是策略选择，因此闸门顺序为
`lifecycle → fuse → 重入锁 → 敞口 → 资金`。

**落点（仅拦开仓腿，平仓腿放行）**：


**盘中强平（`force_close` 状态）**：`execute_round` 结束后追加一轮「只平不开」：


### 4.4 T2.2-4 移仓执行与账本原子迁移

**执行顺序（逐品种串行，禁止并腿）**：

```
平旧（全平，SHFE 拆平今/平昨）
  → 等终态（≤30s，复用 book.active_orders + pump）
  → 校验 net_size == 0
  → 开新（同方向同手数）
  → 等终态
  → sync_stops 自动重建（见下）
```

- 平旧未全成 → **中止该品种开新** + `roll_failed` 告警，下个执行轮重试（不半途开新，避免双份保证金）；
- 平旧成、开新未成 → 记 `pending_open`（symbol → 方向/手数），下个执行轮按新合约补开；
- 全程 `journal.log("roll", ...)` + `live_events` 落库。

**账本原子迁移**（`src/live/ledger.py` 新增）：

```python
def roll(self, *, symbol: str, new_instrument: str, direction: str,
         volume: int, close_price: float, open_price: float,
         trading_day: str) -> dict:
    """换月原子迁移：旧合约平仓结算 → 重映射 → 新合约建仓。

    顺序不可换：先按旧合约平仓（结算已实现盈亏 + 撤销今昨仓分组），
    再更新 instrument_map，最后按新合约开仓——否则 apply_fill 找不到映射。
    """
    old = self.symbol_to_instrument[symbol]
    spec = self.contracts[symbol]
    self.apply_fill(instrument=old, direction=direction, offset=OFFSET_CLOSE,
                    price=close_price, volume=volume, trading_day=trading_day)
    self.instrument_map.pop(old, None)
    self.instrument_map[new_instrument] = symbol
    self.symbol_to_instrument[symbol] = new_instrument
    self.apply_fill(instrument=new_instrument, direction=direction, offset=OFFSET_OPEN,
                    price=open_price, volume=volume, trading_day=trading_day)
    sign = 1 if direction == "LONG" else -1
    cost = (open_price - close_price) * sign * volume * spec.multiplier
    self.roll_cost[symbol] = self.roll_cost.get(symbol, 0.0) + cost
    return {"symbol": symbol, "from": old, "to": new_instrument,
            "roll_cost": cost, "commission": spec.commission_per_lot * volume * 2}
```

**为什么止损不用额外处理**：`sync_stops` 挂在 `TradeRtn` 上（v2.1 设计）。
平旧成交 → `net_size == 0` → `stop_clear`；开新成交 → `net_size != 0` → `register_entry` 按新均价重建。
**换月自动获得正确止损行为**——这是 v2.1 设计的一个意外红利，须用对拍测试锁死（见 §6-T12）。

**但有一个必须补的洞：移仓当天止损「裸奔」。**
重建时 `entry_row = day_idx`（今日入场），而 `_armed` 要求 `row_idx > entry_row` → **换月当日不判定止损**。
新开仓这样处理是对的（T+1 观察期），但换月不是新开风险，只是把同一笔持仓换了个壳——
让它在换月日失去保护，等于用「制度性空窗」换「口径一致」。

处置：新增 `LiveRiskGuard.rearm_stop(symbol)`，在移仓成交后显式把 `entry_row` 回退一天：

```python
def rearm_stop(self, symbol: str, *, date: str = "") -> RiskEvent | None:
    """移仓后立即恢复防护（换月不是新开仓，不吃 T+1 观察期）。

    只改 live 侧持有的 ``StopState`` 字段，不新增 engine 方法（守住红线）。
    """
    st = self.manager.stops.state(symbol)
    if st is None:
        return None
    st.entry_row = self.ledger.day_idx - 1        # 回退一天 → 下一 tick 即 armed
    avg = float(self.ledger.state(symbol).avg_price)
    self.since[symbol] = [avg, avg]               # 极值起点重置为新均价
    self.reg_day[symbol] = self.ledger.day_idx
    return RiskEvent(date, "roll_rearm", symbol,
                     f"移仓后立即恢复防护（基准日 {self.ledger.day_idx - 1}）")
```

**代价如实记录**：这意味着换月日的止损取「新合约当日极值」（跨日口径），若新合约当日已大幅偏离，
可能当天就被平掉。这是**正确暴露**（换月后价格确实到了止损位），记 `roll_rearm_triggered` 事件。

**必须同步更新的三处状态**：

| 状态 | 位置 | 不更新的后果 |
|---|---|---|
| `prev_close` | `risk_guard.prev_close` | 涨跌停判定用旧合约前收盘 → 误判停板 |
| `signal_state.last_close` | `signal_state.json` | 日报 / 手数计算的参考价失真 |
| `stops` | `risk.json` | 已在成交回报链路自动重建（无需手工） |

**`roll_cost` 的诚实口径**：它不是额外现金流，而是「换月导致持仓基准变化的隐性摩擦」。
正数 = 多头换月后成本抬高（不利）。日报单独一行展示，**不并入策略已实现盈亏**。

### 4.5 T2.2-5 R11 启动孤儿委托清理

**能力补齐**（`src/live/ctp_api.py`，沿用现有查询封装风格）：

```python
# TdClient
def query_order(self, instrument: str = "") -> None:
    q = _tdapi.CThostFtdcQryOrderField()
    q.InstrumentID = instrument
    self._throttle_query()
    self._api.ReqQryOrder(q, self.next_request_id())

# _TdSpi
def OnRspQryOrder(self, pOrder, pRspInfo, nRequestID, bIsLast):
    ...  # → OrderQryRsp 事件（order_ref / instrument / status / volume_traded / leaves /
                            #    order_sys_id / front_id / session_id）
```

**启动清理流程**（`LiveRuntime.start()`，`_backfill_stops()` 之前）：

```
query_order() → 等 QueryDone（≤5s）
  → 过滤 status 未终态（未报 / 待报 / 已报 / 部成）
  → 逐笔 order_action(撤单)
  → 等 ActionRsp（≤3s）
  → journal.log("orphan_cancel", ...) + alert()
```

- 本地 `book` 是内存态，重启后为空 → **柜台有、本地无 = 孤儿**，判据简单可靠；
- 撤单失败（已终态 / 已撤）→ 只记事件，不阻塞启动；
- 幂等：撤掉的单下次查不到，重复启动无副作用；
- **CTP 只返回当日委托**，跨日孤儿单日终已失效，无需处理历史。

### 4.6 T2.2-6 R8 退出收尾

```python
def drain_orders(self, timeout: float = 15.0) -> list[ExecNote]:
    """退出前处置在途委托：全撤 → 等终态（超时则告警）。"""
    active = self.book.active_orders()
    if not active:
        return []
    for o in active:
        self.session.order_action(o.order_ref, o.instrument, o.order_sys_id)
    deadline = time.time() + timeout
    while time.time() < deadline and self.book.active_orders():
        self.pump(0.5)
    left = self.book.active_orders()
    ...
```

**挂点**：`LiveRuntime.close()` 开头统一调用（`run_once` / 常驻 Ctrl-C / 异常退出都覆盖）：

```python
def close(self) -> None:
    try:
        self.drain_orders()
        self.save_state()
        ...
```

**顺序不可换**：先撤单等终态，再存状态——否则账本先落盘、撤单回报后到，状态会不一致。

```python
# to_dict()
```

**`since` 必须一起存**：否则同日重启后 `on_tick` 会以「重启后第一个 tick」重建极值，
等价于丢掉了「注册后到重启前」的价格轨迹——在下跌途中重启，止损位可能被低估（该触发的没触发），
或反之。**只修 `reg_day` 是半修**（这是审计新增的 G6）。

## 7. 风险与失效条件（如实记录）
