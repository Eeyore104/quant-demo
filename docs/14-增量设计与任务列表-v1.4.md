## 3. 架构设计

### 3.1 总体原则

- **旁路增强**：新功能挂在「跑批结束后的收尾环节」（与现有 overview 刷新同级）——集成点仅 `run_backtest.py` / `run_portfolio.py` 两个入口的收尾段，回测主流程零侵入；

### 3.3 结果库 Schema（SQLite）

```sql
runs(id INTEGER PRIMARY KEY, kind TEXT,            -- backtest | portfolio
     symbol TEXT, strategy TEXT, params_json TEXT, -- 单品种字段；组合为 NULL/摘要
     start_date TEXT, end_date TEXT, initial_capital REAL,
     total_return REAL, max_drawdown REAL, sharpe REAL, win_rate REAL,
     trade_count INT, total_commission REAL,
     health_verdict TEXT, risk_enabled INT,        -- 体检结论 / 风控开关状态
     report_html TEXT,                             -- 本次报告文件路径
     meta_json TEXT,                               -- git 短哈希 / 数据区间 / 环境摘要
     created_at TEXT)
trades(run_id INT REFERENCES runs(id), symbol TEXT, direction TEXT, offset TEXT,
       date TEXT, price REAL, lots INT, commission REAL, pnl REAL)
risk_events(run_id INT REFERENCES runs(id), date TEXT, symbol TEXT,
            kind TEXT, detail_json TEXT)
data_quality(batch_id TEXT, symbol TEXT, check TEXT, status TEXT,
             detail TEXT, created_at TEXT)
```

- 写入时机：两入口收尾段自动登记（`storage.enabled`）；明细量级小（单次回测数十~数百笔），一次性写入；
- 查询：列表 / 单条详情 / 多 run 对比 / 质量批次汇总（供看板与脚本共用）；
- 数据库文件在 `output/` 下（天然不进 git）；WAL 模式（单机多读单写安全）。

### 3.4 数据质量校验（T1.4-2）

| 检查类 | 内容 | 严重度示例 |
|---|---|---|
| 完整性 | 相邻 bar 间隔 > N 个自然日（剔除长假近似）→ 疑似缺口；最新日期距今 > N 交易日 → 不新鲜 | warn |
| 异常值 | OHLC 逻辑（low ≤ open/close ≤ high）；价格 ≤ 0；单日涨跌幅超阈值（默认 15%，超停板常识值的跳变多为数据问题）；成交量/持仓为负 | error |
| 一致性 | 清洗后 vs 原始缓存行数差超阈值；品种区间与配置不一致 | warn |
| 版本标记 | 每批次记录：时间戳 + 各品种行数 + 最新日期（支持两次批次差异对比） | info |

- 交易日历：akshare `tool_trade_date_hist_sina` 拉取后缓存 `data/raw/trade_dates.csv`（一次拉取离线可用）；拉取失败时降级为「相邻间隔」启发式；
- 输出：`output/reports/data_quality.md`（人读）+ 登记 `data_quality` 表（机读）；入口 `scripts/check_data.py`（默认组合品种池，`--all` 扫全部有缓存的品种）。

### 3.5 HTML 报告（T1.4-3）

- 生成器 `src/report/html_report.py`：字符串模板（复用 overview 的 CSS 手法），图片 **base64 内嵌**（自包含、断网可看、单文件可发送）；
- 两个模板：`build_backtest_html(...)`（单品种：绩效表 + 体检结论卡 + 样本外表 + 图）/ `build_portfolio_html(...)`（组合：汇总 + 逐品种 + 风控摘要 + 开/关对比 + 图）；文本内容复用现有 `build_report_text` / `build_portfolio_report` / `build_risk_section` 的结构化结果，不重写文案逻辑；
- 文件名：`output/reports/report_<symbol>_<YYYYmmdd_HHMMSS>.html` / `report_portfolio_<YYYYMMDD_HHMMSS>.html`（时间戳保留历史，`keep_history` 可关）；
- **历史图查看设计**：报告自包含 → 历史 run 的完整图通过「打开其报告 HTML」查看（看板直接给链接），**不额外做图归档**（避免文件堆积；最新一次的图在看板直接展示）。

### 3.6 Streamlit 看板（T1.4-4）

- 依赖：`[project.optional-dependencies] dashboard = ["streamlit>=1.40"]`；启动 `uv run --extra dashboard streamlit run dashboard/app.py`；
- 结构：`dashboard/app.py` 为薄展示层，数据准备逻辑全部放 `src/results/db.py` 查询函数（可单测）；
- 页面区块：
  1. **概览**：最近回测列表（runs 表）+ 关键指标卡（最新一次回测摘要）；
  2. **单次详情**：选 run → 指标 + 图（读 `output/figures/` 最新图 + 报告链接）+ 交易明细表；
  3. **对比**：多选 run → 指标对比表（收益 / 回撤 / 夏普 / 成本）；
  4. **体检结论**：健康检查 verdict 汇总视图；
  5. **参数热力图**：展示 `figures/param_heatmap_*.png`；
- 未安装 streamlit 时不报错（入口检测 + 提示安装命令）；主链路完全不受影响。

### 3.7 调度与告警（T1.4-5）

**`scripts/daily_run.py`（一条命令流水线）**：

```
① 交易日判断（周末直接跳过；节假日查交易日历缓存；--force 可强制）
② 更新数据（重拉全区间覆盖缓存：单品种一次请求，8 品种 ≈ 8 次调用）
③ 跑批（默认组合 run_portfolio；--backtest 切单品种）
④ 数据质量检查 + HTML 报告 + 结果登记（复用各模块）
⑤ 汇总通知（成功摘要 / 失败告警 → 企业微信）
```

- 退出码语义：0 正常 / 1 失败（供任务计划判断）；每一步的失败都进入告警消息（哪一步、什么错误）；
- 更新口径：**重拉全区间**（akshare 单次调用成本可控；避免增量合并复杂度；主连历史修正也能顺带吸收）——增量合并列为未来优化。

**`scripts/register_task.py`（Windows 任务计划）**：

- `--install`：`schtasks` 注册 `quant-demo-daily`，每工作日 17:00（`/SC WEEKLY /D MON,...,FRI`），开启 **StartWhenAvailable**（错过补跑，对应"电脑没开"场景）；
- `--uninstall` / `--status`：卸载 / 查看；
- 本机注册后实测：手动 `/run` 触发一次验证闭环（不需要真等 17:00）。

**`src/utils/notify.py`（企业微信）**：

- `send_markdown(text)`：urllib POST；失败重试 1 次；发送失败只记日志（不阻塞主流程）；
- 消息模板：成功摘要（日期 / 品种 / 关键指标 / 报告路径）与失败告警（步骤 / 错误摘要）；
- 配置：`notify.enabled: true` 默认开；URL 缺失时自动降级为日志提示（不报错）——URL 就绪后即可用。

**日志增强**：`logger.py` 增加可选文件输出（`logs/daily_<YYYYMMDD>.log`），仅 daily_run 场景启用；控制台行为不变。

### 3.8 配置结构（示例）

```yaml
storage:
  enabled: true
  db_path: "output/db/quant.sqlite3"
report_html:
  enabled: true
  keep_history: true            # true=时间戳保留历史；false=仅保留最新
notify:
  enabled: true                 # URL 未配置时自动降级为日志
  on_success: true              # 每日摘要
  on_failure: true
quality:
  recent_days: 10               # 新鲜度窗口（交易日）
  gap_max_days: 10              # 相邻间隔告警阈值（自然日）
  jump_pct_warn: 0.15           # 单日跳变告警阈值
schedule:
  time: "17:00"
  weekday: true                 # 任务计划注册用（节假日由 daily_run 二次判断）
```

```yaml
# config/config.local.yaml（可选，gitignore；优先级高于 config.yaml）
notify:
  wecom_webhook_url: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=..."
```

> 读取顺序：环境变量 `WECOM_WEBHOOK_URL` > `config.local.yaml` > 缺省（降级日志）。

## 5. 验收标准（对 docs/07 验收线的细化）

1. **一键跑通**：`uv run python run_backtest.py` / `run_portfolio.py` → 原产出不变 + 新增 HTML 报告 + 结果入库（均可用开关关闭）；缓存后运行时长增量 ≤ 数秒；
2. **结果库**：重复跑批 → runs 累加、明细正确可查；`output/db/` 不进 git；查询函数单测覆盖；
3. **数据质量**：`uv run python scripts/check_data.py` 输出质量报告；对构造的缺陷样本能报出问题（缺口 / 异常值）；日历缺失时降级可用；
4. **HTML 报告**：浏览器打开完整可读（自包含，断开网络仍可看）；单品种与组合各一份；文本与引擎输出口径一致；
5. **看板**：`uv run --extra dashboard streamlit run dashboard/app.py` → 浏览器可交互展示历史回测（列表 / 详情 / 对比）；未安装 streamlit 时主链路不受影响；
6. **调度**：`daily_run` 一条命令完成「更新 → 跑批 → 报告 → 登记 → 通知」；非交易日正确跳过（含 `--force` 演示）；`register_task.py --install` 后可安装 / 查看 / 卸载，手动触发验证通过；
7. **告警**：配置真实 webhook 后收到成功摘要与失败告警各一条（验收时实测一次；未配置时降级为日志）；
8. **零回归**：既有 115 测试零改动全绿 + 新增测试；CI 全绿；engine / strategy / analysis 及 data 既有文件 `git diff` 为空；
9. **确定性**：同一输入重复跑 → 检查结果与报告内容（除时间戳）一致。

## 7. 风险与开放项

| # | 项 | 说明 |
|---|---|---|
| R1 | akshare 拉数稳定性 | 每日更新依赖外部接口；失败 → 告警 + 次日补跑；数据质量检查兜底；重拉全区间天然覆盖断档 |
